# Root acceptance of the projection and public journey

Root reviewed the final SM02 model, query/cursor handling, source validation,
card/basis integration, relationship derivation, route aggregation and the
focused store tests. The concrete queue in REVIEW-SM02-CANDIDATE.md is resolved
at the reported source boundary. This is bounded feature acceptance; final
regression, coherent traceability and package-source proof remain SM05 work.

The projection retains exact caller-selected strategy identity and snapshot;
no global current strategy is guessed. Known non-Atom kinds are explicit
landmarks, while unmaterialized node kinds remain unknown. Membership, index
rows and relationships have separately described finite budgets. The
fabricated exact-record counter was removed; complete source-plan decoding is
explicitly reported separately from emitted page membership.

The shared source loader retains the existing active-contract policy and
caller-shared index budget. Current source fingerprints are exposed before an
assessment exists, enabling a real external client to construct its first
proposal. Blocker evaluation is explicitly NotEvaluated; optional assessment
availability is independent of relationship coverage. Neither means runtime
admissibility or accepted truth.

Root and an independent reviewer checked the reported relationship repairs:
current partition predicates, knowledge direction and conflicting ID values,
direct references and explicit gaps, and read-versus-write meaning. A final
asymmetry was repaired: Fact subject links are AppliesTo from either endpoint;
Region subject and work fields retain separate AppliesTo/Affects meanings.
The real query test compares relationship IDs from both cards. A valid6000-byte
Unicode Fact statement is preserved in its full bounded description and
underlying record, with a short identity-based name.

Route closure counts shared work once. Topological evaluation, rather than
lexical ID order, preserves the reverse-lexical diamond lower bound. Current
typed ranges aggregate as a known subtotal; absent/stale estimates and
resource/scheduling assumptions remain explicit. No feasible-schedule or
complete-cost claim is manufactured from a partial view.

SM02's five registered store/query cases and seven domain library cases pass,
with strict scoped lint/format/conform and zero orphan gate. The public
application journey reads the fingerprint from a card, writes the actual
DataProposal through its configured channel, reads Current through Machine and
authenticated HTTP, and checks unchanged Work. It then verifies exact partial
route values, closes each writer, reopens a new service instance and observes
Stale with no current aggregate. This application reopen is within one test
process; the report now says so. The separate CLI case invokes actual binary
processes through the existing store/request entrypoint and sees the changed
fingerprint after a closed-writer update. Each public target passes1/1.

The initial feature deliberately remains a projection plus optional Work
descriptions/assessments. It introduces no new canonical milestone authority,
automatic estimate-driven dispatch, resource availability inference, graphical
client or NEXT migration. The read-only development pilot separately preserves
21IDs and both49planning/9acceptance dependency kinds; it is not an executed
canonical campaign migration or an empirical model-effectiveness benchmark.
