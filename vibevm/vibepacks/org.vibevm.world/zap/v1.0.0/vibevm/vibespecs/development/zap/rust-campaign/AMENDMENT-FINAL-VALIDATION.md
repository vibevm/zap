# Final validation: refactor correctness and retained algorithm evidence

Owner decision, 2026-09-14. This amendment supersedes campaign instructions
requiring another live-LLM parallel execution as a release gate.

The accepted algorithm need not be demonstrated from first principles again.
Final validation primarily establishes correctness of its Rust transfer and
refactoring, reusing applicable accepted algorithm and integration receipts.
The earlier choice between fresh medium workers and reused xhigh workers is
obsolete; no new live-model run is selected.

Structural edits use compiled public contracts, scoped conformance/lint and
existing behavioral evidence. A changed failure boundary or new mechanism still
needs its own meaningful deterministic oracle: atomic/idempotent spawn
observations, late-start uncertainty, recovery without repeated effects,
current-gate retries, index/reference agreement, bounded navigation, and
acceptance/completion conservation remain required where changed.

R16 finishes the same nonempty two-job campaign through actual Rust runtime,
provenance, evidence, stage, work-acceptance and ApplicationService closure
routes using an explicitly labeled deterministic test driver. Generated inputs
and independent result computation exercise delivered packet/material contracts.
Fixture observations are never reported as actual collaboration launches,
observed inference settings or real released slots. Preserve prior native
refusal receipts as evidence of this session's external harness limit.

Live LLM execution is optional only when an unresolved harness-specific boundary
cannot be checked algorithmically. It is not a general algorithm quality test
or mandatory repetition of accepted results. Likewise, another large-data run
must answer a concrete remaining scaling/resource question; source-only changes
do not invalidate unrelated measurements or authorize ceremonial full panels.

The final report distinguishes retained algorithm evidence, new deterministic
refactor/failure-boundary checks, measured resource behavior, actual installed
artifact checks and unobserved external capabilities. Honest capability limits
remain visible. Required implementation, production gates and the real package
installation/publication checks are not waived by this validation change.
