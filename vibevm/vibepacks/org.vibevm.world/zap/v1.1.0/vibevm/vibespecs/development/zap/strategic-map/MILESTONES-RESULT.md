## Delivered behavior

- Canonical milestones have independent stable identities, observable results,
  consumers, required obligations and typed contributions/dependencies.
- Historical achievement is immutable. Current validity checks actual accepted
  evidence, source applicability and prerequisite proof; task count is not proof.
- Milestones can be introduced dynamically during reassessment. A successor
  adopted plan retains prior identities and obligations, changes focus and keeps
  distant work explicit. Initial preparation cannot be reused as an exemption
  for changes after plan adoption.
- The existing lowering kernel enforces exact refinement plans, causal work
  rationales, retained-work/evidence comparisons, retry lineage, selected research
  and horizon conservation. A new strategy cannot silently disable the policy.
- Information opportunities remain separate from execution resources. Discovery
  creates no Work. Selection uses compatible cost/benefit ranges or an explicitly
  uncertain reasoned proposal, with source freshness, acquisition reuse and
  ordinary execution admission. Stop conditions reach the actual work/packet
  boundary; advisory conditions are identified as such.
- Split, merge, contribution move, route change and retirement have exact previews,
  atomic application, dependency remapping, obligation/consumer conservation and
  preserved dormant alternatives. Connected dependents are rewritten together;
  retired history remains intact. Historical revisions and operations are queryable.
- Canonical milestone, information-opportunity and strategic-fork cards expose
  semantic types, names, purpose/result, actual backing objects and typed relations.
  Machine, authenticated HTTP and compiled CLI journeys exercise the interfaces.
  Existing independent effort/time/complexity/difficulty assessments remain intact.

## Deliberate boundaries

The Owner excluded the comparative agent pilot from this goal. No empirical
productivity improvement is claimed. Graphical rendering remains a separate
client; this implementation provides its semantic data and planning behavior.

Semantic actors still propose domain meaning. The kernel validates bindings,
coverage, conservation and admissibility; it does not infer arbitrary result
meaning from titles. Current-proof evaluation and complete incoming-dependent
discovery disclose their store-wide components instead of claiming constant or
fully local cost. Query-specific limits and missing information remain explicit.

The development performs no NEXT activation, live campaign migration or automatic
publication. Released 1.0.0 source and its public tag remain unchanged.
